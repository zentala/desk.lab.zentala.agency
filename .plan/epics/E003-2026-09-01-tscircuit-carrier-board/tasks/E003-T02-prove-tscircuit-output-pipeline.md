# E003-T02: Prove TS Circuit output pipeline

## Objective

Use a minimal throwaway circuit to prove the selected TS Circuit version can
generate every output promised to reviewers or manufacturers.

## Steps

1. Pin the TS Circuit version and create a minimal test design.
2. Generate schematic, PCB and 3D previews where supported.
3. Export fabrication files, BOM and placement data where supported.
4. Open each output independently and write an export manifest with commands,
   versions, file names and verification results.
5. Record gaps and define a fallback before the actual board is designed.

## Acceptance criteria

- [ ] Install and export are reproducible from a clean checkout.
- [ ] Every generated artefact opens in its intended independent viewer/tool.
- [ ] Unsupported outputs are documented; none are silently promised.
- [ ] The export manifest can be included in the review portal.

## Tests

- Clean-install test.
- Independent file-open test for each generated artefact.

## Implementation note

`hardware/e003-carrier/scripts/prove-pipeline.mjs` proves the core render path;
`artifacts/pipeline-proof/` contains Circuit JSON and standalone schematic/PCB
SVGs. The candidate proof is generated by `prove-candidate.mjs`. The `tsci`
CLI remains environment-blocked by a native Rollup application policy, and
this gap is recorded in `exports/manifest.json`. The dependency-local proof
path now passes `npm ci --ignore-scripts` and `npm run check` from a clean
worktree and records deterministic artifact hashes and diagnostics.
