# E001-T04: Consolidate the assets into one copy; keep the old page for parity

**Wave 1** · sequential · depends on T02.

> **Rewritten 2026-07-29 after the T01 rehearsal.** The original premise — "move master's
> assets into the app" — was wrong. Master brings no assets: they predate the branch split and
> already sit on `dev` under `legacy/`, duplicated into `astro/public/images/`. See
> [../JOURNAL.md](../JOURNAL.md).

## Goal
Collapse the duplicated asset tree to one copy inside the app, and park the old hand-written
page where a content-parity check can read it.

## Acceptance
- **The 19.7 MB image duplicate is gone.** `legacy/images/` and `astro/public/images/` hold 11
  byte-identical files each; one copy survives.
- `legacy/enclosure/` → `astro/public/enclosure/` (via `git mv`, history intact).
- `legacy/index.html` + `legacy/style.css` kept temporarily as `astro/legacy-source/` for the
  content-parity check (removed in [T11](E001-T11.md)).
- `legacy/notes/*.md` already rescued by [T03](E001-T03.md) before this runs.
- Build green (`cd astro && npm run build`).

## Open decision
Images stay in `astro/public/images/` (served as-is) or move to `astro/src/assets/` (Astro
optimizes them at build time). The original plan assumed `src/assets/`; that means rewriting
every `/images/...` reference in the components. Decide at implementation — cheap either way,
but do it before [T07](E001-T07.md) so EXIF stripping runs once, on the surviving copy.

## Notes
